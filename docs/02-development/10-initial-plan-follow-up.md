## 追加した機能

トップ・公開一覧・詳細から、補足や訂正をGitHub Issuesへ届けられるようにしました。詳細ではレポートIDと対象URLを入力済みにした作成画面へ進めます。実際の送信は利用者がGitHub上で行います。GitHubアカウントが必要で、投稿が公開されることをリンクの近くに示しています。既存レポートに記載された連絡先も保持します。

トップと公開一覧に、自動検査・操作確認・再評価の状態を分けて表示します。未確認や未実施を成功として扱わず、架空の結果には「想定」を付けます。CMSで公開された詳細にも同じ状態表示を追加しました。CMS形式の架空の `.example` URLはリンクにせず、架空の対象であることを示します。

## 検証の再実行

Node.js 22とインストール済みのGoogle Chromeを使用します。Chromiumのダウンロードは不要です。

```sh
npm ci
npm run lint
npm run typecheck
npm run build
npm test
npm run test:api
npm run test:cms
npm run test:db
npm run test:ui
```

Chromeが標準の場所にない場合は、`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` に確認済みの実行ファイルの絶対パスを設定します。

UI検証はローカルの本番ビルドとテスト用PostgreSQLを起動します。サンプルモードのトップ・一覧・詳細と、CMS形式の公開サンプルが対象です。画像は `_work/ui/` に保存されます。実Supabase・GitHubへの書き込みは行いません。

全4画面で1280px・320pxの表示とaxeの自動検査を確認します。サンプルモードの3画面では文字サイズを200%にしたときの横はみ出しも確認し、トップと詳細の間の移動はキーボードで検証します。200%の確認はCSSの文字サイズ変更であり、ブラウザの実ズーム操作ではありません。axeはWCAG 2.2までのA・AAタグに該当する自動検査で、VoiceOverの読み上げやサイト全体の適合を証明するものではありません。
