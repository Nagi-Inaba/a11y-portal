# 評価の仕組み

URLを指定して自動検査を実行し、評価レポートの下書きを作ります。出力されたJSONは[管理者CMS](05-report-cms.md)でDBへ取り込み、操作確認の結果を追記して公開できます。

## 1. 実行

```sh
npm run evaluate -- <url> [--site <サイト名>] [--scope <確認範囲>] [--out <path>]
```

例:

```sh
npm run evaluate -- https://example.com/guide --site "サンプル市 公式サイト"
```

`src/data/reports/<id>.json`へ書き出します。初回はブラウザの取得が必要です。

```sh
npx playwright install chromium
```

## 2. 出力されるのは下書き

このコマンドが埋めるのは自動検査の結果だけです。人による操作確認のタスクは、未確認の雛形として書き出します。

| 項目 | コマンドが埋める | 人が記入する |
| --- | --- | --- |
| `automatedScan` | ○ | |
| `tasks` | 雛形のみ | ○ |
| `contact` | | ○ |
| `scope` | 引数があれば | ○ |

`tasks[].outcome`は`not-verified`で出力されます。人が確認して書き換えるまで、レポートは未確認のまま表示されます。自動検査だけで公開できないようにするための仕組みです。

## 3. データ構造

評価の単位は達成基準ではなく、**利用者が達成したいこと**（`Task`）です。

```text
Report
├── automatedScan     ページ全体の自動検査結果。タスクには紐づかない
│   ├── findings      違反として報告された項目
│   └── needsReview   自動では判断できず、人の確認が必要な項目
└── tasks[]           人による操作確認。評価の単位
    └── findings[]    その操作で困った箇所
```

自動検査はページ全体を対象とするため、特定の操作には紐づきません。`Task`とは別の器に入れ、画面でも分けて表示します。

### WCAGの扱い

達成基準は`relatedCriteria`という名前で持ちます。「この基準に違反している」という判定ではなく、困りごとを理解し改善につなげるための**参照**です。

コンセプト4.2の「サイト全体の適合判定に広げない」方針を、データ構造の段階で守るための命名です。1ページの検査結果から「このサイトはAA非適合」と読み替えられないようにします。

対象はWCAG 2.2のA・AAです。WCAG 2.2は2023年10月5日にW3C勧告となり、2024年12月12日に更新されました。WCAG 3.0は草案の段階のため採用しません。

達成基準の日本語名と解説リンクは`src/lib/evaluate/wcag-criteria.ts`にあります。網羅表ではなく、自動検査で現れるものを中心に用意しています。未収録の基準は番号のまま出力されるので、必要に応じて追記してください。

## 4. 自動検査の限界

axe-coreは機械的に判定できる範囲しか検査しません。キーボードだけで目的の操作を完了できるか、読み上げで意味が伝わるかは含まれません。

**問題が報告されないことは、その操作を完了できることを意味しません。** この文はレポートの`coverageNote`にも記録され、画面に表示します。

`needsReview`は「問題がある」ではなく「自動では判断できなかった」項目です。断定を避けた文言で出力し、人の確認を促します。

## 5. 検証

```sh
npm test
```

`node --test`とNode 22の型ストリップを使うため、テスト用の依存は追加していません。

書き出し前に`parseReport()`で検証します。形式が崩れたデータを公開側へ渡さないためです。必須項目が欠けている場合は、どの項目かを示して失敗します。
