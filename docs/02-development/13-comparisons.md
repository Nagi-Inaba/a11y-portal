# AI・人・自動検査の比較

2026年9月14日。フェーズ4の比較条件、独立実行、人による確認、公開画面をローカルに実装しました。本番DBへの適用、ワーカー配備、実モデルの課金実行は行っていません。

## 比較の流れ

管理者が、登録済み対象の目的・共通手順・成功基準・読み取り操作の許可範囲を固定して比較を登録します。同じ比較IDに改善前・改善後の実行を蓄積し、自動検査、AIの操作、人の操作結果を分けて表示します。公開前に人が結果と限界をレビューします。実行の失敗・中断も記録し、成功や検出0件へ置き換えません。

対象は管理下のテストページ、または許可済みの読み取り操作です。ログイン・入力・送信・購入は対象外とします。共通開始条件は、新しいブラウザ、ログインなし、日本語、1280×900pxです。許可したクリック対象とキー操作だけを実行し、ページ内の指示から許可範囲を増やすことはできません。

管理者は `/admin/comparisons` から条件を登録し、「改善前」「改善後」を指定して実行します。登録後の条件は変更できません。対象ページを改善してから同じ比較に別の実行を追加してください。条件自体を変える場合は、新しい比較を登録します。

実行が終了すると、OS・ブラウザー・支援技術・実施日時・実際の手順・結果・制約を記入できます。共通条件で実施したことを確認して保存します。人による結果はレビュー前まで編集でき、レビュー後は固定します。AIの自己報告について「確認できた／確認できなかった／判断不能」を記録します。「確認できた」には、完了した実行と保持中の観察ログが必要です。

改善前後の両方がレビュー済みになったら、比較の解釈と未確認範囲を記入し、公開可否を確認して公開します。`/comparisons` に公開一覧、`/comparisons/<比較ID>` に共通条件と3種類の結果を表示します。公開はその時点のレビュー済み実行の写しです。追加の実行を自動で公開することはありません。公開停止も管理画面から行えます。

## 実行とデータの境界

AI接続はOpenAI Responses APIを使用します。モデル名・APIキー・入出力単価はワーカー環境で明示し、設定がない状態では外部APIを実行しません。1実行8回までの判断、子プロセスは全体240秒、AI操作は190秒、親プロセスの回収期限は270秒、DBの実行権は300秒です。期限切れは中断として残し、自動では再試行しません。1回の応答は最大1000トークンです。拒否・不完全な応答・不明な使用量・許可外の指示は失敗として記録します。

管理者が指定する実行予算は0.01〜1米ドルで、ワーカー側の上限との小さい方を適用します。入力のバイト数と余裕分から費用を見積もり、DBへ予約額を保存してから呼び出します。予算が足りなければ次の呼び出しを行いません。使用量が取得できない失敗では予約額を残します。表示額は設定単価による見積もりであり、提供元の請求額を保証するものではありません。単価やモデルの設定を変える場合は運用側で履歴を保持してください。

受付は管理者1人につき24時間の申請予算合計5米ドル以内、同じ比較につき最大200実行です。同じ対象の自動検査と比較は同時に受け付けず、受付間隔は5分以上です。対象を停止すると待機中の比較は中断し、実行中の比較も次の進捗保存から拒否します。既に送信したAPI呼び出しの取り消しや返金を保証しません。

ブラウザーはDB認証情報・OpenAI APIキーを引き継がない子プロセスで起動します。ワーカーは専用のSupabase Authアカウントで実行権だけを取得し、サービスロールキーを使いません。接続先は登録済みoriginと公開IPv4に限り、DNS検査したIPへ接続します。

AI操作では移動先URLと資材URLを分けて登録します。画像・CSS・JS等の資材は最大50件です。すべての通信種類にURL完全一致を適用し、HTTPリダイレクトは追従前に遮断します。移動先URLが許可済みでも、別URLへのリダイレクトは許可しません。APIRequestContextによる1ホップ取得は同じプロキシを通ります。そのHTTP CONNECT80対応は比較処理だけの設定で、通常の自動検査の設定は変えません。

クリックは指定したCSSセレクタの可視・有効な要素に限り、実行直前に再確認します。フォーム・入力欄・送信ボタン・ダウンロード・ポップアップは対象外です。キー操作はTab、Shift+Tab、Escape、上下矢印、Home、Endに限り、入力欄等ではTab・Shift+Tab・Escapeだけを許可します。任意のJavaScript、文字入力、Enter、Spaceはモデルの操作として受け付けません。自動検査は登録済みoriginの1ページをaxeで検査するため、AI側のURL制限とは範囲が異なります。結果には検査範囲を残します。

送信する情報は、共通条件、直前までの操作記録、最大12000文字のメインフレームの表示テキスト、許可した要素の名前・状態です。隠れた本文、フォーム内の本文、入力値、Cookie、認証情報、HTML全体、画像は送信しません。表示文字列やラベルに秘密情報を載せたページは登録しないでください。iframeやShadow DOMの本文はこの観察方法では網羅しません。画面テキストの観察はスクリーンリーダーによる読み上げ検証とは異なります。

APIでは`store:false`を指定します。これはAPIから後で取得するための応答保存の指定であり、提供元のデータ保持全体をゼロにする指定ではありません。[Responsesの仕様](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)と[データの取り扱い](https://developers.openai.com/api/docs/guides/your-data)を参照してください。応答形式は[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)のJSON Schemaを使い、さらにアプリ側で操作内容を検証します。

画面観察の内部ログは30日を過ぎると読み取り対象から外れ、次のワーカーの取得処理で削除されます。ワーカー停止中は物理削除も遅れます。操作・モデル・使用量・失敗・レビューの記録は比較の根拠として保持します。公開用のJSONはフィールドを限定し、観察本文、利用者ID、実行権のトークン、未知のメタデータを除外します。ただし、AIの説明やレビュー本文は公開対象なので、人が公開前に内容を確認します。

## 導入

既存の投稿・自動検査のマイグレーションに続けて `supabase/migrations/20260914020000_comparisons.sql` を適用します。管理者は `report_admins`、専用ワーカーは `scan_workers` に登録します。登録方法とChromeの確認手順は[自動検査ワーカー](12-scan-jobs.md)と共通です。ワーカーに管理者権限は付けません。

Webアプリとは別のワーカー環境に、次の変数を設定します。実際のキーをリポジトリや画面へ書かないでください。

| 変数 | 内容 |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 同じDBの接続設定 |
| `SCAN_WORKER_EMAIL` / `SCAN_WORKER_PASSWORD` | 専用ワーカーの認証情報 |
| `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` | 確認済みのGoogle Chromeの絶対パス |
| `OPENAI_API_KEY` | ワーカー専用のAPIキー |
| `OPENAI_MODEL` | Structured OutputsとResponsesに対応するモデル名。既定値なし |
| `AI_INPUT_USD_PER_MILLION` / `AI_OUTPUT_USD_PER_MILLION` | 選択モデルの100万トークンあたりの入出力単価。正の値 |
| `AI_MAX_RUN_COST_USD` | ワーカーの1実行上限。0.01〜1 |

環境変数を設定したシェルで `npm run comparison:worker -- --once` を実行すると、待機中の比較を1件処理します。継続稼働は `npm run comparison:worker` です。モデル未設定のまま比較を作成することはできますが、実行は待機のままです。まず管理下のページで、資材URLと許可した操作が期待どおり動くことを確認してください。

## 検証と残る範囲

ローカルの制御したページ、モデル応答の代替、テスト用PostgreSQLを使用します。実SupabaseやOpenAIへの書き込み・課金呼び出しは検証に含めません。

```sh
npm run build
npm test
npm run test:comparisons
npm run test:comparisons:browser
npm run test:comparisons:worker
npm run test:comparisons:ui
```

ブラウザーを使う検証では、確認済みのGoogle Chromeのパスを環境変数に設定します。DB・API試験では改善前後の3種類の記録、権限・CSRF、実行権・版の競合、公開前の制約、期限切れ、観察の保持期限、公開停止を確認しました。ブラウザー試験では、読み取りクリック、フォーム・入力値・非表示本文の除外、画像・iframe・リダイレクトを含む未許可通信の遮断を確認しました。モデル代替試験では費用・回数制限、予約保存前の送信禁止、拒否・不完全応答・不正操作を確認しました。CLI試験は、実際の子プロセスとIPCを使い、不正な対象をモデル呼び出し前に拒否して失敗を保存する経路を確認しています。

独立したセキュリティレビューで、画像・iframe・リダイレクトからの未許可URLへのアクセスを指摘され、修正と対象を絞った再レビューを完了しました。既存の投稿・公開・自動検査の回帰試験も実施しています。

画面試験では、登録→改善前後の実行依頼→人の確認→レビュー→公開→公開停止を実際のフォームで確認しました。登録・待機・人の結果・公開画面を1280pxと320pxで検査し、横はみ出しとaxeの自動検査違反は検出されませんでした。自動検査の通過は、VoiceOverやすべての利用条件での操作を保証しません。

実モデルでの成功経路と請求額、クラウド環境でのプロセス回収、複数PostgreSQL接続による同時負荷、本番反映後の導線、VoiceOver実機操作は未確認です。テスト用PostgreSQLはPGliteのため、実サーバーの多接続負荷を再現した証跡にはなりません。
